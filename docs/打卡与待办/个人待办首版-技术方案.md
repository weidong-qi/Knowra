# 个人待办首版：技术方案

日期：2026-11-09。状态：已按第 7 节六个批次实现（PR #357）。未实现与后续事项见 [后续与未实现事项](后续与未实现事项.md)。
需求依据：[规划与需求](规划与需求.md)（第一至九节）。本文只定技术做法，不改需求。

## 1. 范围

**做**：主线／支线、多层子任务、支线升级与移入主线、状态（进行中／已暂停／已完成／已归档）、暂停联动、计划日期与截止日期、今天视图（今日安排／之前未完成／今日已完成）、计划视图、星标、手动排序、下一步推导、完成收尾、撤销完成与删除、归档封存、一次性提醒。

**不做**：打卡、经验等级、时代、笔记关联、日历视图、按小时排程、回收站、局部归档、截止具体时刻（只到日期）。

## 2. 总体结构

待办需要在 Mac 与云端（网页）之间同步，因此**不走任务工作区的独立扩展模式**，而是作为一个新的同步集合 `personalTodos`，接入现有原子实体同步（与人工训练资产 `training-assets-v1` 的接入方式相同）：

| 层 | 位置 | 说明 |
| --- | --- | --- |
| 共享类型与纯逻辑 | `packages/web-core/src/personal-todos/` | DTO、命令规则、下一步推导、今天分组、提醒计算；前后端共用 |
| API 领域与服务 | `apps/api/src/modules/personal-todos/`（`.ts`） | 命令 → 校验 → 一次事务写入多条实体；`app.factory.js` / `postgres-app.factory.js` 装配 |
| 存储 | JSON 核心集合、SQLite 核心表、PostgreSQL 新表与迁移 | 三种驱动都实现；PostgreSQL 失败不回退 JSON |
| 同步 | `modules/sync/` 新增 `todo-batch-domain.ts`；`desktop-runtime` 的 `entity-batches` / `entity-sync-state` 识别新集合 | 新能力 `personal-todos-v1` 列为必需能力（实体 schema 版本保持 9，握手由必需能力拦截旧端） |
| 前端 | `apps/web/src/features/personal-todos/` | hash 路由 `#/learning/...`（今天、`plan`、`mainlines`、`mainlines/:id`、`sidelines`），只用 `components/ui/` 组件；同步冲突沿用现有冲突卡片 |

不加入搜索与 AI 授权。

### 同步要点

- **一次命令 = 一个变更批次**。暂停父任务、连同下级完成／删除／归档等会改多条记录的操作，本地在一个事务里写完，并作为一个原子批次推送，云端整批接受或整批拒绝。
- **云端再校验一遍规则**（`todo-batch-domain.ts`）：父级存在且不成环、层级 ≤5、顶层才能是主线／支线、归档子树内的记录不能被改或删、归档需整棵已完成。违反时整批拒绝，和其他集合一样进入冲突处理。
- **只做软删除**：同步不接受待办硬删除（`TODO_SYNC_DELETE_UNSUPPORTED`）；已归档记录任何改动都被拒绝（`TODO_ARCHIVED`）。
- **同批提交**：Mac 端把所有待改待办合成一个同步批次，避免整棵树被拆开后单独校验失败。
- **冲突**：同一条待办在两端都改过时，按现有实体冲突流程处理（采用云端／采用本机），不做字段级自动合并，也不提供「保留两份」。个人使用下两端同时改同一条的情况很少。
- **提醒状态随同步**：投递后用 `ackReminder` 把提醒标为「已提醒」或「已错过」，随同步传到其他设备；本机另有投递记录防止多个窗口重复弹出。两台设备在同步前同时到点，仍可能各弹一次，首版接受。
- **升级顺序**：因为是必需能力，云端与 Mac 应用必须一起升级；旧版 Mac 应用会被提示升级，本地数据与待同步修改保留（现有机制）。

## 3. 数据模型

单一聚合 `Todo`，主线和支线都是顶层节点，用 `kind` 区分：

```ts
interface Todo {
  id: string;
  parentId: string | null;     // 顶层为 null
  kind: 'mainline' | 'sideline' | 'item';  // 顶层只能是前两者
  title: string;               // 必填，≤200
  note: string;                // 说明，≤5000
  goal: string;                // 仅主线：目标与完成标准
  order: string;               // 同级排序键（分数索引字符串，插入不重排兄弟）
  starred: boolean;
  status: 'active' | 'paused' | 'done';
  pausedBy: 'self' | 'parent' | null;  // 区分单独暂停与随父暂停
  pauseReason: string | null;
  plannedDate: string | null;  // YYYY-MM-DD
  dueDate: string | null;      // YYYY-MM-DD
  completedAt: string | null;
  archivedAt: string | null;   // 非空即封存，整棵子树一起写
  reminder: Reminder | null;
  revision: number;            // 乐观并发
  createdAt: string; updatedAt: string;
}
type Reminder =
  | { kind: 'fixed'; at: string /* ISO，带时区偏移 */; state: ReminderState }
  | { kind: 'beforeDue'; daysBefore: number; time: 'HH:mm'; state: ReminderState };
type ReminderState = 'pending' | 'fired' | 'missed' | 'cancelled';
```

- 「今天」以设备本地日期计算，日期字段只存日期，不存时区。
- 层级上限暂定 **5 层**（需求第十二节未定，可调）；支线步骤允许继续嵌套，规则与主线相同。
- 进展数字统计**直接下级**的完成数，暂停项计入总数但单独标注。

## 4. 命令（服务端唯一写入口）

网页端与 Mac 端都走本机 API `POST /api/todos/commands`（Mac 写本地 SQLite 再由同步推送），请求体带 `operationId`（幂等）和目标节点的 `expectedRevision`，一次命令在一个事务内完成：

`create` / `update` / `move`（换父级或排序）/ `promote`（支线升主线）/ `pause` / `resume` / `complete`（可带 `includeChildren`）/ `reopen` / `delete` / `restore`（撤销删除）/ `archive` / `setReminder` / `ackReminder`。

读取：`GET /api/todos`（全部未删除节点，前端在内存里组装各视图；个人数据量下足够）。

服务端强制的规则：
- 归档子树内任何写入、以及删除归档节点的祖先，返回 `TODO_ARCHIVED`。
- 有未完成下级时 `complete` 必须显式 `includeChildren=true`，否则返回 `TODO_HAS_OPEN_CHILDREN`。
- 归档要求节点及全部下级已完成。
- 暂停父级：未完成且 `pausedBy=null` 的下级标为 `pausedBy='parent'`；恢复只解除 `parent` 的。
- 完成、删除取消未触发提醒；暂停时提醒仍为 `pending` 但不投递；恢复时已过时间的标为 `missed`。
- 截止日期变化时 `beforeDue` 提醒随之重算；固定提醒不动，冲突由前端提示。

**撤销**：删除为软删除（`deletedAt`），前端提示条 10 秒内可 `restore`；之后作为同步删除提交（墓碑随同步传播）。完成的撤销就是 `reopen`。不做回收站。

## 5. 提醒投递

需求明确不承诺未验证的平台行为，首版如实限定：

| 端 | 方式 | 应用关闭时 |
| --- | --- | --- |
| Mac 应用 | 渲染进程每 30 秒检查到期提醒，经已有 `system-notifications.cjs` IPC 发系统通知，成功后 `ackReminder` | **不投递**；下次打开时将错过的标为 `missed` 并在今天视图提示「重新设置」 |
| 网页 | 页面打开时在应用内弹出提示（不申请浏览器通知权限） | 不投递，同上 |

同一设备多个窗口由本机投递记录保证只通知一次；跨设备见第 2 节。系统通知不可用时（网页或系统拒绝），Mac 应用同样退回应用内提示卡。到期 10 分钟内仍会投递，超过即标为错过。

实现（批次 F）：`apps/web/src/features/personal-todos/TodoReminderRunner.tsx` 挂在应用外壳上全局运行，每 5 分钟重新读取一次以接收其他设备同步来的改动；设置入口在详情卡「提醒」一行（`ReminderEditor.tsx`）。

## 6. 前端

- 导航新增「待办」，下设 今天 / 主线 / 支线 / 计划 四个子页；状态与星标为筛选项。
- 快速添加：默认建支线，主线详情内默认建子任务。

## 8. 已确认的决定（2026-11-09）

1. 需要 Mac 与网页同步（见第 2 节）。
2. 接受提醒限制：应用关闭时不通知，下次打开提示已错过、需重新设置。
3. 层级上限 5 层、进展按直接下级统计、删除撤销 10 秒、首版不做拖拽排序。
