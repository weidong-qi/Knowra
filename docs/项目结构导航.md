# 项目结构导航

> 本文档是项目生命周期内持续维护的代码定位地图。它不替代开发规范和设计文档，而是帮助开发者和 AI Agent 快速判断“某类改动应该去哪里改、不要去哪里改”。

## 维护原则

1. 新增一级目录、重要模块目录或跨模块入口时，必须更新本文档。
2. 文件职责发生迁移时，更新对应目录说明和“改动入口”。
3. 本文档只描述稳定边界、关键文件和定位规则，不逐函数罗列实现细节。
4. 文件职责与行数的维护约定见[开发规范](开发规范.md#工程边界)。
5. 若本文档与代码不一致，以代码为准，并在本次改动中修正文档。
6. 在对应章节完善现有结构，不在文末按时间增补。
7. 本文档只描述当前代码结构；历史变更、bug 修复和版本演进写入[工程变更日志](工程变更日志.md)。

### 当前维护关注点

- 编辑器入口保留会话和接线所有权；已分离的保存、视口、附件、标注、笔记链接和依赖已保存正文的动作，不再回填进页面组件。
- `apps/web/src/store/slices/workspaceSlice.ts` 的剩余 mutations 与 `packages/web-core/src/api/workspace-api.ts` 的其他领域客户端仍可复查；只有出现清晰独立职责和回归依据才继续抽取。
- `apps/api/src/modules/ai/` 的 catalog 授权与投影边界，以及 `apps/api/src/infrastructure/local-data-relations.js` 的顺序校验与原地修复，保留现状；不能为了缩短文件改变错误顺序或权限语义。
- `apps/desktop-runtime/src/entity-sync-state.mjs`、`apps/desktop-runtime/src/sqlite-data-store.mjs` 保留原子状态所有权；桌面 main、安全 IPC 和退出链路不在缺少原生证据时机械拆分。
- 本轮有限审查的收益、批次证据与未决风险见 [质量审查收尾总结](审查/2026-10-12-质量审查收尾总结.md)；历史记录继续写入唯一工程日志。

### `docs/AI功能`

模型接入设置位于 `apps/web/src/features/settings/ModelConnectionSettings.tsx`；`ModelRuntimeStatus.tsx` 只读取既有助手运行状态。API 与桌面分别由 `ai/model-settings.ts` / `desktop-shell/src/model-settings.cjs` 保存凭据；`apps/api/test/run-model-settings-tests.js` 可运行已注册的模型设置回归，覆盖三端支持模型与固定错误消息契约。

模型 Gateway 的 adapter 位于 `modules/ai/infrastructure/providers/deepseek-adapter.ts` / `mock-adapter.ts`，子目录已全部迁 TS；具名请求、读取与流端口保留实际消费，原始供应商响应仍由既有 Gateway 验证，子进程入口继续由现有 esbuild 打包。

本轮笔记助手：`ai/note-privacy.ts` 统一原资料隐私检查；`ai/action-inbox.js` 投影持久成果、修订与重新预览；`ai/agent-checkpoint.ts` 定义有界恢复与持久模型响应；联网工具通过宿主注入合成适配器，未接真实搜索供应商。具体当前范围见 [四包实施](AI功能/07-笔记助手四包实施.md)。

对话附件基础位于`ai/conversation-attachments.js`与`ai/conversation-attachment-routes.ts`，私有schema/store限定原文件和未解析状态；`ConversationAttachmentPicker`仅文件信息与受保护图片本地预览，不发送模型。未审parser目录、依赖和自动调用已移除；当前能力与后续边界见[对话文件输入](AI功能/08-对话文件与图片输入实施计划.md)。

[AI 功能开发工作区](AI功能/README.md) 保存需求共识、用户流程、可插拔架构、数据/工具/权限契约、任务与验收。当前重点为可故障隔离的 AI 底座和对话式笔记 Agent：授权内自动检索，新稿与差异稿先进入成果收件箱，用户确认后采纳。未来正式试题/日常测试与批改走专门系统流程。P0/P1 已有基础记录，新共识差距见 [P1 对话 Agent 补齐方案](AI功能/06-P1对话Agent补齐方案.md)，实施进度统一在 [任务表](AI功能/04-分阶段开发任务.md)；规划与历史验收不代表当前上线能力。

沉浸式助手页位于 `apps/web/src/features/assistant/AssistantView.tsx`，成果审阅为同目录 `AIInbox.tsx`，当前会话成果匹配见 `reviewTarget.ts`，引用历史原文的读取、校验与会话/关闭失效统一由 `useConversationSourcePreview.ts` 管理，工具调用记录的折叠展示、工具标签与结果摘要由 `ConversationTrace.tsx` 负责，按需读取与缓存仍在助手页编排；纯文本安全展示组件为 `ReadableMarkdown.tsx`，输入区附件入口为 `ConversationAttachmentPicker.tsx`。三态合成截图与边界见根目录 [design-qa.md](../design-qa.md)。

### `apps/desktop-runtime`

`src/http-shutdown.mjs` 统一 HTTP 与 MCP 服务的退出排空：仅回收零输入、从未开始 HTTP 请求的预连接，保留部分请求与响应的自然排空，并额外等待断线后仍执行的 handler。`runtime-server.mjs` 继续负责 MCP、HTTP、同步、AI、SQLite 与目录锁的关闭顺序；外壳只记录固定阶段枚举，不记录请求或用户数据。

`src/knowledge-lifecycle-boundaries.mjs` 只为本地业务事务保存知识回收／恢复的 outbox 描述符；`sqlite-data-store.mjs` 同事务登记，`entity-sync-state.mjs` 保留发送边界、级联失效与后继修改，`sync-engine.mjs` 对冻结解除保持绑定一致。沿用 batch2，私有标识不上传；能力合同要求 `knowledge-lifecycle-v1`。真实存储／页面与发布边界见 [桌面资产补齐](离线编辑与同步/桌面资产补齐-实施与验收.md)。

训练六集合通过 `sync/training-batch-domain.ts` 校验领域终态和题目版本；`question-objective-identity.js` 保持存活关系身份、重建已删除关系时产生新 ID。`knowledge-lifecycle-boundaries.mjs` 同时保留四训练主体的明确回收／恢复，`exam-focus-review-boundaries.mjs` 只记录实际考点确认所需审阅依赖前像及 frozen 回执绑定，保持确认后修改父项的既有 Web 语义。能力合同同时要求 `training-assets-v1`，不扩展正式试卷或作答模型。

`authoritative-purge.mjs` 在原有五类手工资产接口前执行联网预检、原 token／世代／版本核验、待核对结果持久化和真实删除事实对账；`sync-execution-gate.mjs` 与 scheduler／configure／disconnect／restore 共用排空边界。云端 `asset-purge-task-state.ts` 从实际私有 JSON／SQLite／PG 记录读取任务与历史，`asset-purge-guard.ts` 为领域清理补齐失败关闭和事务内世代核验。V4 `store/assetPurge.ts` 仅组织专用清理能力、原预检参数与待核对状态；通用 `permanentDelete` 保持关闭，不能用于离线物理清理。

`src/sqlite-deletion-facts-contract.mjs` 定义必需核心删除账本 v1 与只读严格校验；`sqlite-deletion-facts.mjs` 保存有限已知事实、建立升级保护副本并提供成员门禁。`sqlite-data-store.mjs` 在来源回填前初始化账本，普通净删除同事务留证，普通写入检查 absent→live，业务 import 规范化后早检并在提交事务内重查。两个同步状态入口保存已核正修订墓碑。`backup.mjs` 默认只校验格式，恢复入口另外使用 `restore-readiness.mjs` 比较当前/候选事实和来源；`sqlite-provenance-projection.mjs` 与真实启动共享合法旧 receipt 投影。`restore-directory.mjs` 在候选内保留 target scope 和双向事实，运行时等待同步与 AI 完整排空后 fresh 重查，完成事务才发布指针。合同、结构图和合成验证见 [05C1](AI功能/p3/AI-03-05C1-SQLite已知删除事实与导入门禁.md) 与 [05C2](AI功能/p3/AI-03-05C2-完整恢复删除事实与发布屏障.md)。

`src/sync-transport.mjs` 负责同步 HTTP 请求、网络错误分类、超时与响应封装；连接地址和内存认证值由 `sync-engine.mjs` 持有并逐请求注入，首次配置允许显式目标地址。engine 保留世代／游标、上传确认、附件落盘与调度排空，预算请求沿用独立语义。`test/sync-transport.test.mjs` 对照冻结旧实现验证请求与错误轨迹，`test/sync.test.mjs` 验证真实 engine 的连接重试和凭据更新。

省电同步调度入口为 `src/sync-scheduler.mjs`：统一空闲退避、本地提交防抖和恢复唤醒；`sqlite-data-store.mjs` 提供元数据事务与提交后缓存版本。`test/sync-idle-benchmark.mjs` 使用隔离资料库测量空闲 CPU、写入和刷新；打包版验收入口为 `apps/desktop-shell/test/packaged-sync-idle.test.mjs`，复现命令与结果见 [桌面同步省电验收](已归档/离线编辑与同步/桌面同步省电验收.md)。

本地离线运行服务，复用 API 领域服务与 V4 构建，独立于云端启动入口。`src/sqlite-data-store.mjs` 提供业务数据与队列的原子保存；`runtime-server.mjs` 装配回环会话和接口边界，`runtime-services.mjs` 为每个活动资料集装配独立服务，`runtime-session-script.mjs` 隔离恢复前的旧页面；`sync-engine.mjs` / `sync-state.mjs` 负责笔记传输、基线与冲突；`entity-sync-state.mjs` 管理关联组同步与冲突隔离，`entity-conflict-copy.mjs` 为“保留两篇”复制附件归属并改写引用，`entity-batches.mjs` 保持当前正文/标注及必要版本的原子组，旧正文版本与旧标注修订按依赖分批，收集知识/证据/来源版本依赖，云端 `sync/knowledge-batch-domain.ts` 校验证据快照与确认门槛；`snapshot-migration.mjs`、`backup.mjs`、`restore-directory.mjs` 与 `recovery-export.mjs` 管理迁移、备份校验、隔离恢复和救援导出。服务端协议位于 `apps/api/src/modules/sync`，V4 入口位于 `features/sync`；手动恢复旧云端备份后按[删除事实保护流程](离线编辑与同步/同步世代重建与删除事实保护.md)使用 `scripts/reset-sync-epoch.mjs` 重建世代；保留已知墓碑，事实/主体冲突停止，整机回滚的独立权威源仍须核实。`scripts/test-support/postgres-test-database.mjs` 为 API／桌面应用测试创建和清理独立 PostgreSQL schema，`test/postgres-test-isolation.test.mjs` 验证附件文件生命周期污染、并发隔离及失败清理。`test/` 包含真实存储、HTTP、数据库及故障测试，`test/e2e/` 运行真实页面。桌面封装由 `apps/desktop-shell` 提供。

`assistant-service.js` / `assistant-routes.ts` 保留旧版任务入口与只读回看；`conversation-service.js`、`agent-worker.js` 负责新会话和有界工具循环。`access-service.js` 核查持续授权及逐请求外发，`retrieval.js` 是候选索引与当前授权版本之间的安全入口，`keyword-search.js` 是默认检索和故障回退。`read-context-service.js`、`worker.js` 仍服务旧版短时范围任务；`record-*` 与 `contracts/` 管理私有记录，核心校验、状态、SQL 映射与同步/PG 仓库已迁为 `.ts`；`record-types.ts` 定义六类基础记录、同步/异步端口与原始事件读取边界，`record-infrastructure-types.ts` 定义状态及 SQL 存储实际使用的最小端口。实际生成受配置、预算及外发门禁控制。

`conversation-records.js` 统一六类会话持久记录的 schema、语义与跨记录引用校验，返回隔离副本，不读写存储；JSON 私有状态及 PostgreSQL/SQLite 适配器直接使用该契约。`conversation-store.js` 保留事务内状态操作与旧契约导出兼容，租约、原子性和数据格式不变。冻结输入、错误优先级及合成适配器边界回归见 API runner 注册的 `ai-conversation-records.test.js`；真实持久化回归仍使用各存储测试。

`agent-request-context.ts` 纯组装普通/授权历史、来源凭据哈希、授权问题与无授权消息文本；保持历史过滤顺序和 UTF-16 长度裁剪。`agent-worker.js` 仍负责授权复核、请求来源预算重试、外发及恢复。边界回归见 `ai-agent-request-context.test.js`，mock 请求集成见 `ai-agent-r04.test.js`，由 API runner 显式注册。

`agent-knowledge-provenance.ts` 为 Agent/MCP 提议生成白名单来源摘要，绑定回执与完整来源哈希并调用严格来源验证器；`.js` 保留五个同身份导出。plan/candidate/origin 只声明读取所需的最小视图，未验证字段仍为 unknown；共享 quote hash 仅按 primitive string 支持域调用。提议与提交服务、record-contract 及共享 hash 实现保持独立，不把该叶子称为整个提交链端到端严格化。

`proposal-progress.ts` 根据工具结果与当前来源窗口纯计算知识提炼进度、待提交判定和模型提示；不读取存储或执行工具。`agent-worker.js` 消费结果并保留原 `proposalProgress` 导出兼容。纯规则回归见 `ai-proposal-progress.test.js`，现有工具与有界循环场景见 `ai-knowledge-propose.test.js`，均由 API runner 注册执行。

`recovery-scope.ts` 登记恢复任务并在关闭时停止新准入、等待在途任务；`runtime-lifecycle.ts` 为同一 AI runtime 复用关闭所有权。API 的完整启动恢复链、应用 context 关闭和桌面启动／配置后的恢复复用该边界；原生 HTTP `server.close()` 保持原语义，持库宿主需显式等待 AI 关闭后才断开存储。复现、调用约定及验收见 [启动恢复与关闭竞态](AI功能/p1/启动恢复关闭竞态-修复与验收.md)。

关键词覆盖由 `access-service.js` 的 `findAuthorizedSearchCandidates` 先在当前授权与扫描预算内筛选，`keyword-search.js` 再对最多 300 篇匹配候选验证版本、评分和引文；`verifyRead` 的受信可选单篇上限保护复核前的正文增长，普通 R02 read 默认行为不变。回归入口为 `ai-keyword-coverage.test.js` 与真实数据库条件套件 `ai-keyword-coverage-postgres.test.js`，规则及全空间列表读取边界见 [覆盖验收](AI功能/p2/授权关键词检索覆盖验收.md)。

`reviewed-price-profile.ts` 是 API 与 desktop-runtime 共用的 `deepseek-flash` 已复核人民币价格档案；本地有效期到点拒绝，其他模型不能套用。`budget-ledger.js` 按相同计费账户/北京日期保留未知用量占额，刷新价格版本不清空旧预留。公开来源、装配链路及离线边界见 [核价刷新验收](AI功能/p1/核价刷新-2026-10-02验收.md)。

## 共享包

### `packages/web-core`

V3 与 V4 共用的框架无关浏览器业务核心。包含 API envelope/client/workspace API（加载、创建、重命名、收藏、删除与回收站 mutation）、workspace 类型、normalization/cache/loading/write guard，以及 `note-file-actions.ts` 中的副本命名、导出文件名与 HTML 文档生成纯规则；源码不依赖 DOM、React、CSS 或任一应用目录，`dist/` 由各前端的 predev/pretest/prebuild 自动生成。

`src/api/attachment-api.ts` 统一附件列表、上传、重命名、删除预检、校验、恢复、清理状态与重试的九个客户端方法，只依赖注入的 `RequestJson`；`workspace-api.ts` 组合为原有扁平 `WorkspaceApi` 并保留上传输入类型的旧出口。各方法既有请求与宽松响应契约不变。

`src/api/command-note-search.ts` 定义可选 `WorkspaceApi.searchCommandNotes` 能力、当前空间的查询契约以及数量/片段上限，严格验证四字段命中 DTO；它不承担 renderer 交互或授权判定，V4 和服务端分别绑定当前空间与校验 owner。

### `packages/content-anchor`

API 与 V4 共用的无 DOM Markdown 来源投影。输出可见文本到原文 UTF-16 半开区间、结构路径、内容块与标题边界，并提供浏览器可用的 SHA-256、v2 anchor 校验及仅唯一候选自动重定位。不依赖 ProseMirror 坐标，不执行任意首个同文匹配。

`src/index.js` 仅保留显式公共导出，内部模块直依实现，不回导入口。`src/projection.js` 统一 Markdown 投影与范围／块／章节锚点基元，`src/hash.js` 保存原哈希算法；`src/anchor-resolution.js` 编排静态解析、重定位和章节跟随，并复用列表解析。

动态跟随入口：`src/source-edit.js` 定义单步来源编辑及重放，`src/dynamic.js` 负责范围继承与稳定结构身份，`src/source-diff.js` 组合离散源码变更。`src/list-projection.js`、`list-anchor.js`、`list-identity.js`、`list-follow.js` 分别负责列表层级投影、完整子树锚点、列表结构身份继承与成员／父项变化确认，列表不走同文重定位；`test/dynamic.test.js` 与 `test/list.test.js` 覆盖编辑、空块／空项、拆合、移动及边界行为。

`test/dependency-layers.test.js` 防止包内依赖环和实现反向导入公共入口；公共兼容回归固定旧版输出，检查导出全集与内部实现引用。身份影子只共享哈希，继续保留独立公式解析与 S1／S2a 保存契约。

API 的 `annotation-change-context.js` 只记录保存前正文并维护旧结构表 `Note.annotationStructure`（I4c 删除）；历史锚点保存在 `AnnotationRevision`；PostgreSQL 迁移为 `e_annotation_tracking`。

`apps/api/src/modules/knowledge/domain/evidence-health.ts` 统一按重点、笔记、历史版本与证据摘录推导来源健康，供本地关系校验和同步／异步知识服务共用；适用性与审核状态仍分别维护。

`apps/api/src/modules/knowledge/application/legacy-annotation-anchor.ts` 在只读旧重点时按其不可变来源版本换算正文标记引起的偏移，映回当前源码范围并排除标记语法；来源校验、预览、分析范围和局部排除复用该规则，不对真实正文编辑做旧锚点跟随。

重点内联化 I4a（2026-11-02）起，V4 不再推算旧重点位置：`annotationTransactionRanges.ts`、`annotationEditJournal.ts`、`editorAnnotations.ts`、`annotationShadow.ts`、旧写入与迁移入口均已删除，保存只提交正文。`editorBlockIdentity.ts` 仍维护块 `blockId`（只在编辑会话内使用，供整段代码重点继承和粘贴副本换新 ID），不再有 `knowraAnnotation` mark。I4b 起服务端也不再跟随旧重点：API 的 `reconcile-annotation-source.js`、`annotation-identity-*.js`、`annotation-range-preview.js`、`resolve-stored-annotation.js` 已删除，旧格式重点写入返回 `ANNOTATION_LEGACY_REMOVED`；正文标记重点的来源证据降级在 `application/inline-annotations.js`（`inlineSourceChanges`）。`packages/content-anchor` 里的旧链路导出与 `annotationStructure` 字段留给 I4c。桌面真实页面回归入口为 `test/e2e/annotation-code-boundaries.test.mjs`、`annotation-list.test.mjs` 和 `annotation-inline-sync.test.mjs`；API 的 `test/inline-annotations.test.js` 覆盖正文标记派生与来源变化，桌面 `test/sync-format-gate.test.mjs` 验证同步格式门禁，`apps/desktop-shell/test/packaged-list.test.mjs` 验证 Mac 打包应用退出重开。当前本地逻辑格式 8、同步实体格式 9，保留已有 SQLite 物理表版本与同步世代。

重点内联化（《重点标记内联化方案》）：`editorKnowraMarks.ts` 定义 mark `knowraMark` 与块属性 `knowraBlocks`，并通过 `createKnowraMarksCodec` 在解析器、序列化器入口与正文标记互转（规则在 `@study-accelerator/shared/knowra-marks`，块内偏移换算复用 `content-anchor` 的 `identityBlockModels`）。`editorKnowraClipboard.ts` 负责复制副本的统一 ID 映射、章节排除关联和代码内的纯文字重点区间；`editorPasteBehavior` 接管含标记的粘贴，`editorBlockIdentity` 按最终插入范围规整，并区分剪切/拖动。I1 只做格式支持，未开放新建入口。服务端 `application/inline-annotations.js` 在保存后从正文派生 `schemaVersion: 3` 的重点行，并在装配层区分"只改标记"的保存（I2）。

S2b-1 块身份表存放在可选的 `annotationStructure.identity`，不替换旧链路 `nodes`：API `application/annotation-change-context.js` 负责随保存写入、沿用或失效；`sync/batch-domain.ts` 丢弃不合法的诊断表而保留同步正文。I4a 起 V4 不再提交编辑器身份快照，I4b 起服务端也不再写入身份表；字段本身留给 I4c。

### `packages/shared`

`src/pdf.js` 与 `.d.ts` 通过 `@study-accelerator/shared/pdf` 提供 PDF 资料与标注的契约、校验和 50 MiB 上限，浏览器、API 与桌面运行时共用。

`src/incremental-review.js` 与 `.d.ts` 提供浏览器/离线共用的增量报告有界契约、审阅选择与非授权草稿导出与严格恢复；内部按验证、提案、envelope、session 拆分。`scripts/experiments/knowledge-incremental/review-envelope.mjs` 是实验审查门适配层，`export-review.mjs` 只负责离线文件转换。见[审阅契约说明](../scripts/experiments/knowledge-incremental/REVIEW-ENVELOPE.md)。

`src/attachments.js` 与 `.d.ts` 通过 `@study-accelerator/shared/attachments` 提供资源路径单次解码、保守文本/结构化附件引用识别及上传/恢复大小上限。API 删除预检与同步校验直接使用，V4 经 web-core 出口使用；`test/attachments.test.js` 验证路径与 hash 冲突、异常编码及来源引用。源码直接发布，无独立编译。

`src/knowra-marks.js` 与 `.d.ts` 通过 `@study-accelerator/shared/knowra-marks` 解析、去除、插入正文中的 Knowra 标记（行内 `<mark data-k>`、块级 `<!--k id ...-->`），规则见《重点标记内联化方案》第 2 节；`test/knowra-marks.test.js` 含随机往返测试。

`src/http-limits.js` 统一路由 JSON 字节限额，桌面批次使用最终请求计量；`src/http-origin.js` 提供 API／Web 共用的写来源判断，只接受具体白名单及同源，并将代理信任限制为显式回环连接。它们不依赖 HTTP server 或存储。

维护规则：

- 只放真正跨应用复用的稳定内容。
- 不放依赖 DOM、HTTP server 或本地文件系统的实现。

维护规则：

- 存储目录不是源码目录。
- 默认 `local-json` 驱动的真源路径是根级 `storage/data/knowledge-base.json` 和 `storage/uploads/`；`postgres` 驱动启用后，知识库元数据真源切换为 PostgreSQL，附件仍位于 `storage/uploads/`。
- 附件元数据中的 `storagePath` 应统一存为跨平台相对路径 `storage/uploads/<id>-<safeName>`，不要写死 Windows 反斜杠路径，也不要提交 Linux/macOS 绝对路径。
- 测试或运行产生的数据改动不要和源码重构混在同一个提交里，除非任务明确要求。
