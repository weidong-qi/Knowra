# 开发规范

本文件补充根目录 [AGENTS.md](../AGENTS.md)，记录项目工程与版本约定。用户当前明确要求优先于这里的工作流建议；历史方案与归档文档不自动成为当前规范。

## 工程边界

- 视图、业务、数据访问按职责分层；复用现有服务、store/hooks 与 UI 包装层。具体 V4 导入边界以 `scripts/check-v4-boundaries.mjs` 为检查入口。
- 普通业务文件以 250 行作为职责复查提示；400–500 行且职责混杂时优先拆分。按职责拆分，不按行数机械切片。类型、路由、迁移、生成文件、快照、Mock、Schema、图标和常量映射可较长，不混入无关业务逻辑。
- 颜色、字号、间距、阴影复用项目设计令牌；API 地址与环境配置集中管理。无需把每个局部常量都抽成配置。
- 支持 macOS、Windows、Linux/Ubuntu；跨平台开发工具优先使用 Node.js，路径使用 `path.join` / `path.resolve`，文本使用 LF。仅面向 Bash 的部署脚本标明运行环境，使用 `#!/usr/bin/env bash`、`set -euo pipefail`、`command -v`，避免依赖平台不同的 `sed -i` 和 `echo -e`。
- Node.js >=24、npm >=11；根 `engines` 当前只声明 Node 要求，npm 是开发环境约定。

## Git 工作流

- 开始修改前查看当前分支与工作区状态，保留已有改动。
- 首次接手仓库/机器、准备同步或推送、或需要远端状态时，fetch 并比较实际 upstream；不要硬编码 `origin/main`。没有共同祖先时先说明差异，禁止用强推解决。
- 本地领先远端是正常开发状态；仅在影响任务时说明。远端领先时结合当前改动选择同步方式，不因一次普通编辑自动执行 `pull --rebase`。离线时可继续不依赖远端的工作，涉及远端的结论需注明未核验。

## 前端

- 基础控件复用 `apps/web/src/components/ui/`；交互状态与业务数据分离，样式放 CSS Modules 和全局 tokens。
- 按钮只用 `components/ui/button/` 的四类：`Button`（文字按钮，`primary` 为橙色主操作，另有 `default` / `ghost` / `danger`）、`IconButton`（仅图标，`tone` 为 `ghost` / `floating` / `primary`）、`SegmentedControl` + `SegmentedButton`（一组里选一个）、`PressableButton`（目录树、列表行等自带样式的整行可点元素，只提供按压与焦点行为）。业务代码不直接写原生 `<button>`，`check:boundaries` 会对遗留处给出提醒但不失败。类别不是封闭的：需要新增按钮类别或新的 variant / tone 时，先向用户说明场景和理由、得到确认后再加入组件库，不要在业务 CSS 里另写。
- 形状按用途共存：小型操作按钮、图标按钮、工具栏搜索和分段切换保留胶囊/圆形；文档页签、目录选中背景、表单、菜单项、提示块和卡片使用小圆角矩形。复用 `--radius-pill` 与 `--radius-control/tab/popover/panel`，主题不覆盖通用圆角。`Button` 默认胶囊，需矩形时显式使用 `shape="square"`。
- 外壳常驻，各主面板独立滚动；不以 window 滚动替代应用布局。
- 业务确认、输入与提示使用项目弹窗，不使用 `alert` / `confirm` / `prompt`。上传和导入允许由用户操作触发浏览器文件选择器。
- 保持内容优先、动效克制。用户指定的页面、截图和参考优先；历史视觉探索不自动覆盖现有 tokens。

## 后端

- 路由负责协议适配，业务流程放应用服务，持久化放 repository。响应使用 AGENTS.md 定义的项目封装，避免泄漏持久化内部字段。
- PDF 主文件使用独立二进制流（50 MiB），不扩大全局 JSON 或普通附件限额；阅读资源随应用离线打包，标注独立于 Markdown 锚点。迁移及恢复入口见 [PDF 首版实施](PDF阅读与标注/首版实施与验收.md)。
- PostgreSQL 事务保护数据库操作，外部文件/网络 IO 放在事务外；保留 JSON 原子写入、引用校验、导入和删除协调机制。
- 批量读取优先复用现有查询能力；新增并发写入、迁移或导入流程时，验证其原子性和失败恢复，不引入无关的分布式锁方案。

## CI 验证与发布门禁

本节记录 `.github/workflows/ci.yml` 与 `scripts/ci.mjs` 中不易从配置本身看出的约束和理由。修改 CI 前先阅读本节；配置变化导致规则不再成立时，同步修改本节。2026-10-18 并行化改造的耗时基准见[归档记录](已归档/CI验证与耗时.md)；改造后的耗时未复测。

### 触发与候选产物

- PR 自动执行完整 CI；main push 再验证实际合并提交并生成 Linux 发布候选。
- 不为 `codex/**` 等分支的 push 重复跑全量。无 PR 的分支通过 CI 的 `workflow_dispatch` 手动全量验证并生成 Linux 候选；手动入口需先合入默认分支才在 Actions 中可见。
- Mac 候选（`mac-build.yml`）由 PR、main push 和 `workflow_dispatch` 触发；Mobile 与 Android 工作流各自维护触发和覆盖。
- 只改实验脚本、实验工作流（`knowledge-*.yml`）和知识模块讨论记录时，`paths-ignore` 跳过全量 CI，由实验工作流运行自己的无费用测试。CI 不运行真实模型实验，不读取模型密钥。
- 同一 ref 的新运行取消旧运行（`concurrency` + `cancel-in-progress`）。

### 并行分组

完整套件分成四个独立 runner，分组以 `scripts/ci.mjs` 为准：

- `api`：`test:api`，保留自定义注册 runner 与后续 provenance node:test。
- `web`：content-anchor、shared、web-core、V3、现役前端、scripts，按此顺序运行。
- `desktop`：`test:desktop`，含 SQLite、CAS、同步、恢复、重启与 MCP 等测试。
- `chromium`：desktop-runtime `test:e2e` 生产页面与离线运行，以及现役前端移动端证据用例。

约束：

- **每个分组都要有自己的 `postgres:17` 服务**、显式测试 URL / 写入开关、Prisma 生成和迁移。API、脚本和浏览器测试也含 PostgreSQL 分支，只给 desktop 配数据库会让其他组的 PG 用例静默跳过。
- 各 runner 的回环地址和文件系统相互隔离，不共享 SQLite 文件或 PostgreSQL 实例。桌面及浏览器使用 `--test-concurrency=1`，API 注册 runner 串行；调整分组时不顺带改测试内部并发、断言、重试或超时。
- 各分组以相同检出 SHA 独立构建生产前端，并验证 release identity 与 source map 缺失。此前构建基准约 5 秒，优先选择简单重建，不引入跨作业产物传递或基于 lockfile 的 dist 缓存。
- npm 缓存由 setup-node 按 lockfile 管理；每次 `npm ci --ignore-scripts`，不缓存 `node_modules`、Prisma 生成物或数据库。Chromium 安装包含系统依赖，不缓存浏览器。
- 快检（空白检查、前端架构边界、迁移后的 API TypeScript、CI 契约回归和生产依赖审计）独立执行，不等待长测试。
- 矩阵 `fail-fast: false`，某组失败仍收集其他组结果。隔离容器 smoke 是独立作业。

### 汇总与发布安全

- 检查名 `Node 24 · build and test` 保留为 always 汇总作业；`checks`、`suites`、`isolated-image` 必须全部 success。失败、取消、跳过、缺失或未知前置作业均拒绝通过。
- main push / 手动触发仅在汇总通过后重建同一 SHA 并打包；打包或上传失败同样使汇总失败。PR 不上传 Linux 发布包。
- CI 主工作流的 runner 检出时不保存凭据（`persist-credentials: false`），权限保持 `contents: read`。使用 `pull_request`，不使用 `pull_request_target`；不为 CI 增加 Secret 或外部服务。
- 合成截图和证据由 Chromium 作业上传。Mac 候选由其工作流核验身份、签名及合成场景。
- 本地未启动 PostgreSQL 的结果不能替代 CI 全量验收。

## 版本与提交

- 使用 SemVer；版本以根目录、`apps/api`、`apps/web` 的三个 `package.json` 为准并保持一致，共享包允许独立版本。
- 修复、文档/脚本修复与依赖 patch 归 PATCH；兼容的新功能、模块或接口归 MINOR；不兼容 API/schema 或重大目录迁移归 MAJOR。先记录 Unreleased，可合并小改动发布；发版时更新三个正式清单及相关 lockfile，V3 归档版本保持独立，不为每次编辑自动发版。
- MAJOR 变更先说明兼容性影响并由用户决定。Agent 不自行打 tag；需要发布标签时告知用户 `git tag vX.Y.Z`。
- 提交使用 Conventional Commits：`<type>(<scope>): <中文简述>`。type 使用 feat/fix/docs/style/refactor/perf/test/chore/ci/revert；不兼容变更加 `!` 或 `BREAKING CHANGE:`。不改写历史提交。

验证按受影响行为与架构边界选择；已有检查通过后，仅在新改动、失败或未解决风险出现时扩大范围。
