# 后端 TS 迁移计划

`apps/api` 从 JS 渐进迁移到 TypeScript 的长期任务。**每批怎么做见 [迁移规范](迁移规范.md)**；本文只记录目标、剩余范围和进度。第 1–60 批的逐批详细记录保存在 [第1至60批详细记录](第1至60批详细记录.md)，只供查阅，不再续写。

## 目标

- API 层获得与 V4 前端同等的 strict 类型保障，`tsc` 作为 AI 改代码时最快的反馈。
- API DTO 与 `packages/web-core` 共用一份契约类型。
- 渐进推进：`.js` 与 `.ts` 混用，每批可以单独合并、单独回退；类型迁移不夹带功能改动。

## 运行前提

Node 24 默认开启类型剥离，直接运行 `.ts`，无需构建；Docker 镜像为 `node:24-bookworm-slim`，Mac 构建用 esbuild 打包，也原生支持 `.ts`。`apps/api/tsconfig.json` 已开启 `allowImportingTsExtensions`、`erasableSyntaxOnly`、`verbatimModuleSyntax`。

| 检查 | 命令 | 范围 | CI |
| --- | --- | --- | --- |
| strict | `npm run typecheck:migrated -w @study-accelerator/api` | 全部 `.ts` 及共享契约类型测试 | 阻塞（`ci.yml`） |
| 宽松 | `npm run typecheck:api` | 全部 `.js` + `.ts`（checkJs） | 仅报告（`code-style.yml`） |
