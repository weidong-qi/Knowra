# 同步暂停后的人工恢复流程

本流程优先保存本机意图，提供显式作废旧同步编号后的安全恢复入口。不包含 SQLite v8、安装、部署或真实资料维护。

## 触发条件

提交已经开始但响应丢失、超时、无法识别或本机确认落库失败，或遇到 `OPERATION_REUSED`、回执淘汰、世代改变、旧版遗留请求及身份不匹配时，保留原请求、本机实体、后继编辑、outbox 和旧基线并持久暂停。崩溃后首次进入普通同步或冲突入口也先检查未确认发送。

## 用户看到什么

状态显示“云端同步已暂停”，专用恢复会显示备份、屏障及下载阶段。重启、网络恢复、重新登录、“立即同步”、普通配置及普通冲突处理不能解除暂停。本机保存与编辑仍可继续。不要手改设备编号、操作 ID 或数据库元数据，也不要用旧版应用打开同一资料库。

## 用户可执行的操作

1. 保留原资料目录。可先打开“本机备份与恢复”另做备份，并导出冲突恢复记录；JSON 不能替代数据库与附件备份，内容可能包含私人笔记。
2. 在恢复区域明确确认旧编号永久作废，以及服务端同步记录格式升级的兼容后果，再发起恢复。临时登录只存在内存，关闭面板后需重新输入，不写入资料库或备份。
3. 应用先创建完整本机备份，校验清单、SQLite、私有记录、已就绪附件及当前整库记录绑定，再持久保存固定恢复编号、新发送编号和原请求身份。失败则不作废旧编号。
4. 应用在原服务、所属资料库建立事务屏障，持久保存可验证证明，再取得固定云端快照。原请求、旧基线及 outbox 此时仍不清理。
5. 查看分页对照及展开的本机/云端资料。整个关联组只能明确选择“保留本机当前状态”或“采用云端快照”，不猜测旧请求是否执行，不自动重放历史回收或恢复动作。
6. 最终选择前再次核对屏障、新编号未被使用、世代、对照版本，并创建和验证第二份完整备份；随后在一个 SQLite 事务内归档双方状态及原始历史、应用选择、更新基线和独立发送身份。失败整体回滚并保留暂停。

## 每个操作的后果

- 结果未知或重启时，继续同一恢复会话、同一恢复编号和同一新编号。不能重新生成编号绕过结果核对；已确认屏障丢失或旧服务不支持屏障时停止。
- 下载过期可沿用屏障重新取固定快照；新快照或任何本机后继编辑会使旧对照失效，必须刷新后重新选择。
- 本机选择保留当前撤回和显式缺席删除，即使当前值等于旧基线也继续记作待确认意图。快照后云端又变更时进入普通关联冲突，不能覆盖本机选择。
- 云端选择先封存最新本机资料、原请求、原 outbox、旧基线及删除事实。永久删除或来源保护仍然有效，不能用云端选择复活禁止恢复的 ID；此时可核对后选择合法的本机删除，或停下人工处理。
- 两种选择都保留私有任务仍需的本机历史副本，不重新上传已退役版本；历史生命周期与确认记录只归档，不在新编号下逐条重演。
- 全局设备编号及私有任务身份不变，只切换独立同步发送身份。以后每次同步在拉取或写入前核对累计屏障，发现作废账本丢失则再次持久暂停。
- 新编号仍受原白名单约束，应用不会自行扩权；未核对的永久清理命令不能通过换号撤销。恢复出的另一 dataset 副本不能自动复用旧会话或占用已使用的新编号，需保全后人工处理。

## 数据不丢失的依据

发送状态先落库，结果未知时不清除冻结请求或后继意图。固定恢复编号和屏障证明跨重启保留，固定快照及决定版本防止迟到结果覆盖编辑。两份经过只读校验的完整备份，加同一 SQLite 事务中的原始记录归档和状态切换，保障失败回滚后仍可核对。普通同步继续验证累计屏障，不能凭空确认旧请求未执行。

## 缺口与未验证范围

- 通用备份仍可保全损坏原始资料，但恢复入口只接受通过校验且与本机全部持久记录一致的备份。失败产物保留供救援，不当作恢复成功。
- 备份检查验证标记 ready 的普通附件、可用 AI 对话附件及任务工作区文件；原本缺失、未就绪的附件不会凭空恢复字节，仍保留对应状态和现有文件证据。
- 服务端升级的是 journal v2，不是 SQLite v8。本机数据库仍为 v7，尚不能从格式层阻止不理解这些标记的旧应用读取；禁止通过应用降级恢复同步。
- 裸服务端旧备份回滚不受支持，须使用[保留作废账本的内容回滚](同步编号作废与安全回滚.md)。旧安装包、物理断电及真实资料演练不在合成测试结论内。
