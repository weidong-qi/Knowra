## 0. 全局规则（所有任务都适用，不得例外）

### 0.1 禁止事项（未得到用户在对话中的明确"同意"前一律不做）

1. 不提交到 `main`、不推送、不创建/更新 PR、不合并、不部署、不安装到本机 `/Applications`。
2. 不读取、复制、修改、删除真实笔记数据（`storage/` 下的运行数据、用户资料库、真实 SQLite/JSON 文件）。只用合成数据或临时目录。
3. 不把数据传到任何新的外部位置（包括私有 Space、网盘、其他云机器），除非用户点名同意了具体位置和具体文件清单。
4. 留存到期**不等于**授权删除。任何到期资料只核对、只报告，不处理。
5. 不做任务范围外的重构、改名、格式化；不整仓库跑 Prettier；不顺手修存量 lint。

### 0.2 授权请求的写法

需要授权时，单独发一条消息，只包含：要做的动作、目标（分支名/仓库/路径）、涉及文件清单、可否撤销。**发出后停在这一步等待回复**，不得并行推进依赖该授权的后续步骤，也不得在没有回复时推定同意。

### 0.3 基线与分支

- 每个任务开始时执行 `git fetch origin`，以**当时的 `origin/main`** 为基线，在报告第一行记录基线提交短哈希。
- 当前 `origin/main` 已包含 #330（控件外观统一），夜间候选是在更早的主线上做的，所有候选都要先 rebase/重放到新基线再验证；有冲突时记录冲突文件并停下汇报，不要自行改写对方逻辑。
- 分支命名：`codex/<任务简称>-20261107`，一个任务一个分支，不混装。

### 0.4 测试结果的汇报规则

- 每个结果写明：命令、基线哈希、候选分支、通过/失败/跳过数。
- **不同阶段、不同组合的数字不得相加**。
- 失败项必须和主线基线失败名单逐项比对，分成三类：①主线同样失败（环境基线）②主线通过、候选失败（新增失败，必须处理）③候选通过、主线失败。

### 0.5 真实 PostgreSQL 的启动方法（本机 macOS）

```bash
initdb -D "$TMPDIR/kpg" -U knowra --auth=trust
LC_ALL=C pg_ctl -D "$TMPDIR/kpg" -o "-p 54329 -k /tmp/kpgsock -c listen_addresses=127.0.0.1" -w start
createdb -h 127.0.0.1 -p 54329 -U knowra knowra_inline_test
export KNOWRA_SYNC_TEST_DATABASE_URL=postgresql://knowra@127.0.0.1:54329/knowra_inline_test
export KNOWRA_SYNC_TEST_ALLOW_WRITES=1
```

socket 路径必须短，必须设 `LC_ALL=C`。macOS 没有 `timeout` 命令，不要使用。测试结束后 `pg_ctl -D "$TMPDIR/kpg" stop` 并删除临时目录。

  - 需要改运行逻辑才能通过类型检查；
  - `test:api` 出现主线没有的失败；
  - 某文件被 `.js` 路径从外部（package.json、脚本、子进程、打包配置）引用，而不在 3.4 的 F/G 表中；
  - 单批 diff 超过 800 行且无法拆分。

### 3.6 每批报告格式

```
第 N 批：<范围一句话>
文件：<改名的文件列表> ；删除转发：<列表或"无">
验收：strict 0 / 宽松 0 / test:api <通过>+<通过> / eslint 0
剩余：纯 JS <数> ，转发 <数>（3.2 命令）
发现的问题：<无 / 一句话 + 是否单独提交>
```
