## 做了什么

- 按旧协议顺序取得并持续持有 `startup.lock` gate 与 `runtime.lock`；检查期旧版启动和第二个救援均在现存 gate 处拒绝，不再短暂改动源根目录。普通 runtime 取锁协议不变，救援不启动普通 runtime、不加载或迁移应用 schema。
- 两层锁释放验证创建身份；不删除替换锁或他人锁。可验证的死进程 runtime 锁只在准备期按旧协议恢复，遗留 startup gate 仍保守拒绝，不按时间猜测删除。
- 检查边界建立后记录全源树身份和纳秒修改时间，附件/草稿通过验证身份的只读 FD 读取；SQLite 只在私有 DB/WAL/SHM 副本打开。发布前后源树有任何增删、内容或目录时间变化即拒绝成功结论。
- 源内、符号链接和大小写/Unicode 等目录身份别名目标均拒绝；目标父目录须已存在，新增目录与文件独占创建，父目录被替换时停止。救援临时目录必须位于源根外，通用快照 helper 也在创建副本前拒绝位于 DB 父目录内的 TMPDIR。
- 导出保留未来 schema、损坏草稿/异常普通文件 uploads 的字节、活动恢复资料集和归档草稿；清单最后写入，未知输出条目阻止发布。失败撤销自有清单，仅清理仍属本次的文件；不递归删除替换物或未知条目。
- 独审反例驱动补齐：Mac 大小写别名、临时目录/文件替换、同 token 替换锁、未知输出条目；SQLite 受控初始化读取后登记延迟生成的 WAL/SHM，正常关闭仍清理自有副本。

## 未完成与原因

- 从准备到释放的整个调用仍不是源根目录零写入：仅协调锁及其真实造成的根目录时间变化被用户接受；检查/导出阶段对源文件和目录零写入，不伪造时间。
- 冷、空或 hot `-journal` 均按 #333 保守拒绝；不在原库判断或执行 journal 恢复，不删除日志。
- 原始救援包保留异常字节不代表可以激活损坏结构。当前为必须先关闭运行服务的离线救援，不提供正在运行 owner 的自动排空/恢复编辑。忽略互斥协议的外部写入会使本次检查失败，不能替代操作系统权限边界。
- 强制杀进程可能遗留私有副本及协调锁；不自动删除未知/被替换目录或遗留 startup gate，应保留现场核对。正常失败路径已验证清理自己的副本和锁。
- 未做真实 Mac 降级、断电或生产部署演练，未开始后端迁移；Linux/Windows 与不同文件系统最终以 CI/后续平台验证为准。
